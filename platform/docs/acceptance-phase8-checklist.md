# Phase 8 上线稳定性与版本归档验收清单

## 验收目标
- Phase 1-7 的功能、验收脚本和人工验收清单形成统一上线基线。
- 上线前有一条可重复执行的 release gate 命令。
- 有版本归档文档，说明本版本包含内容、测试证据、部署检查、回滚路径和上线后冒烟测试。
- 本地服务通过完整回归后，才允许进入生产部署。

## 自动化测试
在 `platform` 目录执行：

```bash
npm run test:release
```

等价于执行：
- 前端 `app.js` 语法检查。
- 后端核心 JS 文件语法检查。
- Phase 1-7 验收脚本。
- API smoke test。
- Phase 1-8 文档存在性检查。

## 人工上线前检查
1. 确认当前分支和工作区变更符合本次发布范围。
2. 确认 `docs/release-v8-baseline.md` 已更新。
3. 本地启动服务并访问 `http://localhost:3002/api/health`。
4. 执行 `npm run test:release` 并确认全部 PASS。
5. 打开平台，使用管理员账号登录。
6. 快速检查客户库、待办中心、管理驾驶舱、知识库复用四条核心路径。
7. 部署前备份生产数据库和当前线上代码。
8. 部署后执行线上冒烟测试。

## 线上冒烟测试
1. 访问首页，确认登录页可打开。
2. 管理员登录成功。
3. 客户库能加载客户列表。
4. 客户详情能打开，并能进入策略/方案/达人模块。
5. 我的待办能加载任务列表。
6. 管理控制室能加载经营驾驶舱。
7. `/api/health` 返回 `{"status":"ok"}`。

## 回滚判定
- 登录失败、客户库无法加载、核心接口 500、页面白屏、Phase 1 主链路断裂，任一出现即回滚。
- 待办、知识库、管理驾驶舱问题如果不影响客户主链路，可先热修；若影响全局 JS 执行，也应回滚。

## 回滚步骤
1. 停止当前 PM2 进程或切回上一版代码目录。
2. 恢复部署前备份的 `platform/server/db/*.db` 或实际生产数据库文件。
3. 重启 `pm2 restart turingmarket`。
4. 执行 `/api/health` 与登录冒烟。

## 不通过判定
- `npm run test:release` 任一检查失败。
- 缺少任一 Phase 验收文档。
- 缺少版本基线文档。
- 本地通过但线上冒烟失败且无法在 15 分钟内热修。
