## Cutover Controls / 切换控制

- Cleanup-control replay accepts only the canonical absent/enabled topologies, idempotently resolves the one exact `.restore.next` residue, validates all control-path parents before mutation, and binds effective PID 1 fragment/Names/DropInPaths across every systemd search root. Public watchdog deadlines are operation-specific: 120 seconds for initial cutover and 7,200 seconds for accepted finalization plus rollback/resume; identity is revalidated before each public link swap and disarm. / 清理控制回放仅接受两种 canonical topology，并在首次变更前验证父链及 PID 1 实际配置；公网 watchdog 的操作专属窗口为初始切换 120 秒、接受态 finalization 与回滚/恢复 7,200 秒，公网切换及解除前均复核 active identity。
- `/var/lib/turingmarket/ppt-cache` is the fifth external state target and is a direct root-only directory, not a release-tree symlink. A first install records the absent origin, creates an empty `root:root 0700` directory only after writers stop, and removes it during pre-mutation recovery only if it remains empty. / 该路径是第五个外置状态目标，为直接使用的 root-only 目录而非发布树软链接；首次安装只在停写后创建，预变更恢复仅在仍为空时删除。
- The per-device capacity gate covers database and PPT snapshots, existing and staged parser runtime, rollback staging, and `node_modules` growth. It requires `max(10%, 512 MiB)` margin and `CUTOVER_CAPACITY_OK` before maintenance or mutation. / 按设备计算的容量门禁覆盖数据库/PPT 快照、现有与待装解析器、回滚 staging 和依赖增量，并在维护或变更前要求上述余量及成功标记。
- Cutover enters all-traffic maintenance, drains parser admissions/spool/units/cgroup, stops and quiesces PM2 plus SQLite, drains the parser again, then prepares the cache and snapshot. / 切换先进入全流量维护并排空解析器，再停止并静默 PM2 与 SQLite，随后二次排空，最后准备缓存和快照。
- `/api/health` must report `status=ok`, `parser.ready=true`, and the exact parser manifest SHA-256. Schema 3 accepted markers bind installed self-test evidence, acceptance facts, and the runtime-tree hash before public traffic can return. / 健康接口必须报告应用与解析器 ready 及精确清单哈希；schema 3 验收标记在恢复公开流量前绑定安装自检、验收事实和运行时树哈希。
