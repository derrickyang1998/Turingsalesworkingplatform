## Delivered

- Commercial input now follows submit-for-review rather than same-user confirmation. Every submission is an append-only draft, and the submitting user cannot approve that version even when they otherwise hold approval capability.
- Added protected `POST /api/campaigns/:id/performance/manual-inputs/:inputId/approve`. Only a different authorized campaign owner or organization administrator can approve the current draft. Repeat approval replays the existing immutable approved version; stale drafts and unauthorized actors fail closed.
- Approval and its sanitized audit event commit in the same immediate transaction. Missing or failed audit storage rolls back the approval.
- Current content projections expose the latest submitted version and latest approved baseline separately. Pending replacement drafts do not remove or change KPI values calculated from the prior approved baseline; list, dashboard, aggregate, and export views switch together only after approval.
- Aggregate financial evidence includes every approved commercial version, a hash-bound aggregate approval identity, the actual approver set, and the latest approval time. Ordinary members receive neither commercial values nor restricted lineage.
- The existing Content Monitor table and data-entry dialog now show compact pending, approved, and restricted states plus an independent approval command. No new page, migration, external provider, Feishu write, AI input, report, proposal, or PPT behavior was introduced.
