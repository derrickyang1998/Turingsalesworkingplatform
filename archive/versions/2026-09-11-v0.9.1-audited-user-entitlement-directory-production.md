## Delivered / 已交付

- Upgraded the existing Admin Control Room User tab instead of creating another admin application. Administrators can search username, display name, email, department, organization, and team; filter enabled state and stable access role; and use keyset pagination. / 直接升级现有管理控制室“用户”页，不新建替代后台；管理员可检索账号、姓名、邮箱、部门、组织和团队，按启用状态与稳定权益角色筛选，并使用游标分页。
- Each user row projects platform, organization, and team roles with active or revoked membership state. Existing create, enable/disable, password-reset, organization directory, AI conversation audit, CRM, M3/M4, knowledge, proposal, and PPT mutation flows remain intact. / 每位用户聚合展示平台、组织和团队角色及有效/撤销状态；既有新增、启停、密码重置、组织目录、AI 对话审计、CRM、M3/M4、知识、方案和 PPT 写入流程保持不变。
- `GET /api/admin/users` remains compatible with `{ users }` and adds bounded `page` metadata. Authentication, platform-admin middleware, and a live database admin check all apply; ordinary and anonymous callers are rejected. / 接口继续兼容 `{ users }` 并增加有界 `page`；同时执行登录、平台管理员中间件与实时数据库管理员复核，普通用户和匿名请求均被拒绝。
- Every privileged list read persists `admin_list_users` in the same immediate transaction. Audit evidence contains only filter names, target user/organization IDs, result count, and next cursor, never the raw query or a reversible query hash. / 每次特权读取都在同一即时事务写入 `admin_list_users`；审计仅包含筛选字段名、目标用户/组织 ID、结果数和下一游标，不保存原始搜索词或可逆摘要。
- AI conversation audit now follows every user-directory cursor, so organizations with more than 50 users retain complete user filtering. A queued refresh prevents an older in-flight user response from overwriting results after account creation or enable/disable. / AI 对话审计会遍历全部用户目录游标，超过 50 位用户时也不丢失筛选项；排队刷新阻止旧请求在新增或启停账号后覆盖最新结果。
