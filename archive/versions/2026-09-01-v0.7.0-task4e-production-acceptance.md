## Release Guard Fix / 发布守卫修复

- The initial accepted-release attempt exposed a deployment-only false failure: immediately after `systemctl reload nginx`, a single raw public health probe could see a transient stale `503` before the graceful reload converged. The release trap then correctly failed closed, but treated that transient as a release failure. / 首次接受态发布暴露了仅影响部署链的误判：`systemctl reload nginx` 后单次公网健康探针可能在优雅重载收敛前看到瞬时旧 `503`，发布陷阱因此按失败关闭，但误把收敛瞬间当作真实发布失败。
- The cutover now invokes the shared exact public Nginx verifier before acceptance facts are finalized. It retries only transient reload states for a bounded period, then validates the public boundary, route contracts, JavaScript MIME, denied paths, and health JSON exactly as before. Non-transient failure remains fail-closed. / 切换现在会在最终接受事实落盘前调用共享的精确公网 Nginx 验证器；它只对重载瞬态做有界重试，之后仍精确验证公网边界、路由合同、JavaScript MIME、拒绝路径和健康 JSON。非瞬时错误继续失败关闭。
