## Delivered / 已交付

- Browser-based administrator reset rejects any active platform administrator and the current company owner with stable `409 PROTECTED_ACCOUNT_RESET_REQUIRES_BREAK_GLASS`. This covers self-reset, peer-admin reset, and owner reset. / 浏览器管理端对所有有效平台管理员及当前企业所有者统一返回稳定的 `409 PROTECTED_ACCOUNT_RESET_REQUIRES_BREAK_GLASS`，覆盖自助重置、同级管理员重置及所有者重置。
- A denied request leaves the password hash and sessions unchanged, does not write a successful reset/rotation audit, and appends only bounded `admin_reset_password_denied` evidence. A former owner can be reset after the authoritative owner changes. / 拒绝请求不改变密码哈希与会话，不写成功重置/轮换审计，仅追加有界 `admin_reset_password_denied` 证据；所有权权威事实变更后，原所有者可恢复普通重置。
- The Admin UI now checks the HTTP status before displaying a temporary password. Non-success responses show the server error and return no success payload. / 管理端界面在展示临时密码前检查 HTTP 状态；非成功响应显示服务端错误，且不返回成功结果。
- The stdin-only credential rotation CLI remains the controlled break-glass recovery path and does not expose credentials in source, browser code, screenshots, or release documents. / 仅从标准输入读取凭据的轮换命令继续作为受控 break-glass 恢复路径，源码、浏览器、截图及版本文档均不保存凭据。
- The trusted schema-v22 structural policy now admits the already-deployed CRM audit event `task_updated`. Schemas v1 and v6-v21 keep their former allowlists, while unknown v22 values still fail closed. / schema v22 可信结构策略接纳既有 CRM 审计事件 `task_updated`；schema v1 与 v6-v21 保持原白名单，v22 未知值继续失败关闭。
- Customer dashboard/detail separation, M3/M4, AI/knowledge, influencer, Feishu, workflow, exports, and frozen PPT were not replaced or expanded. / 客户看板/明细双页面、M3/M4、AI/知识库、网红、飞书、工作流、导出及冻结 PPT 均未替换或扩改。
