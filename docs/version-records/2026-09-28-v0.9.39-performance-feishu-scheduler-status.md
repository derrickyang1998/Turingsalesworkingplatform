# v0.9.39 性能数据飞书定时投递与状态 / Performance Feishu Scheduler Status

日期 / Date: 2026-09-28  
状态 / Status: Production deployed and remotely verified

## 目标 / Objective

在 v0.9.38 的持久 Feishu Bitable outbox 之上，补齐服务端定时检查和可见运行状态。已批准的字段映射由后端按配置间隔检查；有最新观测时生成当前状态与本地日快照投递，使用稳定幂等操作 ID，外部写入配置缺失时严格失败关闭。

Build a server-side scheduled check and visible runtime status on top of the v0.9.38 durable Feishu Bitable outbox. Approved mappings are checked at a configured interval; when fresh observations exist, current-state and local-day snapshot deliveries use stable idempotency operation IDs. Missing external-write configuration fails closed.

## 变更 / Changes

- 新增 `platform/server/services/performance_feishu_scheduler_service.js`：默认 5 分钟间隔、`Asia/Shanghai` 本地日、受限配置范围、确定性 UUID 操作 ID、活动项目扫描、组织管理员执行身份、当前状态/每日快照调度、运行摘要和失败关闭。
- `platform/server/server.js` 启动并停止调度器；`PERFORMANCE_FEISHU_SCHEDULER_ENABLED=false` 可显式关闭，`PERFORMANCE_FEISHU_SCHEDULER_INTERVAL_MS` 支持 1 分钟至 6 小时范围，避免把外部写入配置硬编码在前端。
- `GET /api/campaigns/:id/performance/feishu-deliveries` 新增 `scheduler`：返回 enabled、status、reason、时间间隔、时区、外部写入门控、最近/下一次 tick、映射版本及观测新鲜度。
- `platform/app.js` 与 `platform/client/styles/components.css` 展示服务端自动投递状态；切换活动、保存或批准连接后刷新投递状态，防止旧活动状态污染当前界面。
- `trusted_production_source_manifest.json`、`trusted_production_source_gate.js`、`deploy_v8.ps1` 和 `.gitattributes` 同步新服务及测试文件；无 schema 迁移，生产 schema 保持 v32。

## API、权限与安全 / API, Permissions And Safety

- 保留并增强 `GET /api/campaigns/:id/performance/feishu-deliveries`；原有 `POST /api/campaigns/:id/performance/feishu-sync`、回执和重试路径不变。
- 读取继续遵循活动访问权限；服务端调度只扫描 `approved` 配置和 `active` 活动，并使用对应组织的活动组织管理员身份调用既有投递服务。
- 外部 Feishu Bitable 写入仍由既有服务端配置门控控制；未配置或未启用时调度器只记录 `not_configured` 状态，不创建外部投递。
- 线上验收使用专用 `release-smoke` 身份；不读取、不修改、不轮换 `derrick` 凭据，不使用其做发布烟测。临时认证会话在验收结束后删除。
