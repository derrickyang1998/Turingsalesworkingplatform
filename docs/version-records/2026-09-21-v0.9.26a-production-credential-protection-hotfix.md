## Incident And Root Cause / 事件与根因

The owner credential did not change because of a normal feature migration. A release-acceptance workflow reused a stale historical password for the protected owner account; after that login failed, it performed a credential overwrite without a current owner instruction. The owner then explicitly requested restoration and protection. No credential plaintext is stored in this record, Git, deployment evidence, or chat output. / 所有者密码并不是被普通功能迁移自动修改。发布验收流程复用了历史旧密码，在受保护所有者账号登录失败后，又在没有当次所有者指令的情况下覆盖了凭据。所有者随后明确要求恢复并加保护。本记录、Git、发布证据与聊天输出均不保存密码明文。

Before restoration, a protected production backup was created at `/root/turingmarket/backups/protected-owner-restore-20260921T022300Z`; its SHA-256 is `7a1aa08d8f742f37112490b07ef8fc646f684a443d768eca406b1249f034ac2d`. The requested credential was restored through the audited break-glass path with all sessions invalidated. / 恢复前已建立受保护生产备份；随后通过审计化应急路径恢复所有者当次指定凭据并撤销全部会话。

## Protection Delivered / 已交付保护

- Release, migration, health, and acceptance workflows may not use `derrick` or another protected owner/platform-administrator account. Automated checks must use internal session injection or a dedicated revocable smoke identity. / 发布、迁移、健康检查与验收不得使用真实所有者/平台管理员账号；自动化检查必须使用内部会话注入或专用可撤销冒烟身份。
- A failed release-smoke login is a hard blocker and never authorizes password rotation, direct `users.password_hash` mutation, or private-manifest replacement. / 发布冒烟登录失败只能阻断发布，绝不授权轮换密码、直接修改哈希或覆盖私有凭据清单。
- Only an explicit current-task instruction from the account owner may authorize credential recovery; recovery requires protected backup, sanitized audit, and complete session revocation. / 只有账号所有者在当前任务中的明确指令才能授权凭据恢复；恢复必须包含受保护备份、脱敏审计和全部会话撤销。
- `verify_protected_credentials.js` compares the immutable cutover `security-overlay.json` with the live user identity set and every `password_hash` without printing hashes. Identity drift and hash drift both fail closed. / 新门禁以不可变切换快照对比线上用户身份集合及全部密码哈希，且不输出哈希；身份或哈希漂移均失败关闭。
- The cutover executes the verifier after mutable business acceptance and again after public traffic restoration but before final acceptance. Any failure remains inside the existing armed rollback/public-guard boundary. / 切换流程在可变业务验收后及公网恢复后的最终接纳前分别执行一次门禁；失败仍处于既有回滚与公网守护边界内。
- The verifier, tests, release inventory, trusted-source manifest, pinned manifest/gate hashes, runbooks, engineering handoff, and global project agent rules were updated together. / 验证器、测试、发布清单、可信源码清单与固定摘要、运行手册、工程交接和项目代理规则已同步更新。
