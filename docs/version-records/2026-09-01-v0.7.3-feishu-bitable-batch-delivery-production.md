# v0.7.3 Feishu Bitable Batch Delivery Production Record

## Scope / 范围

- Implementation commit: `06c7dd1`.
- Existing selected-influencer delivery now supports direct Bitable batch create only behind `FEISHU_BITABLE_WRITE_ENABLED=true`; the default remains disabled and keeps the existing CSV fallback. Webhook delivery is unchanged.
- Each enabled write requires a bare UUID `Idempotency-Key`, forwarded as Feishu `client_token`. The server rehydrates active influencer rows and does not trust client-provided record contents.
- The remote table must contain all 20 approved upload columns. Contact data is excluded from outbound records by default while the contact column remains part of the schema contract; `FEISHU_BITABLE_INCLUDE_CONTACT_EMAIL=true` is the separate opt-in.
- The slice validates strict numeric Feishu success, a 500-record limit, exact returned record count, and non-empty remote IDs before it reports success. It intentionally does not add remote-ID persistence, upsert, retry, or reconciliation.
