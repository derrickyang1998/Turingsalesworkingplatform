## Delivery / 交付

- The current M3 proposal screen now calls `/api/ai/proposal-draft` with the active Campaign, audited demand conversation/message IDs, template, authorized knowledge IDs, request ID, and idempotency key. / 当前 M3 方案页向后端方案草稿接口发送 Campaign、已审计需求会话/消息、模板、授权知识 ID、请求 ID 与幂等键。
- Campaign proposal generation is knowledge-only in this slice: web search is fixed off and caller-supplied retrieval limits cannot widen the eight retrieved Campaign chunks. Explicit authorized selections remain bounded by the shared linked-RAG limits. / 本切片方案生成固定仅使用知识库，调用方不能扩大 8 个 Campaign 检索分块；显式授权选择继续受共享 RAG 上限约束。
- Duplicate clicks share one operation; Campaign/context changes invalidate stale responses and restore the real submit control. / 重复点击合并为一次操作；切换 Campaign 或上下文会使旧响应失效并恢复真实提交按钮。
- AI output remains editable. A provider/API failure preserves the deterministic local proposal, and an unconfirmed draft is not archived. / AI 输出继续可编辑；服务失败时保留确定性的本地基础方案，未确认草稿不归档。
- Linked requests no longer call the legacy unscoped similar-knowledge endpoint. The backend RAG result and escaped audit block are the Campaign-scoped evidence shown for the AI proposal. / Campaign 请求不再调用旧版非活动范围相似知识接口；方案显示的依据来自后端 Campaign RAG 与转义审计区块。

## Audit Provenance / 审计来源

- Demand audit IDs are accepted only when the conversation is readable by the actor, linked to the same active Campaign, has `source_module=demand_analysis`, and the message is the matching assistant message owned by that conversation. / 需求审计 ID 仅在会话可读、归属同一 Campaign、来源为需求分析且消息为该会话 assistant 消息时接受。
- The assistant message metadata must also carry the same Campaign ID. Foreign, incomplete, revoked, or misleading provenance is rejected before proposal provider work. / assistant 消息元数据必须携带同一 Campaign；外部、不完整、已撤销或误导性来源会在调用 Provider 前拒绝。
