# v0.9.38 性能数据飞书幂等投递切片 / Performance Feishu Delivery Slice

日期 / Date: 2026-09-28
状态 / Status: Verification ready; production deployment pending
范围 / Scope: Phase 7B bounded delivery slice

## 目标 / Objective

把已批准的性能数据字段映射接入现有飞书 Bitable outbox，使当前状态和每日快照能够在平台内生成可追踪的投递回执，同时保留 CSV 降级路径。该切片不改变既有性能数据录入、分析、AI 复盘、客户报告或 PPT 生成流程。

Connect the approved performance-data field mapping to the existing Feishu Bitable outbox so current-state and daily-snapshot writes have durable receipts in the platform while the CSV fallback remains available. This slice does not replace the existing performance entry, analysis, AI review, customer-report, or PPT workflows.

## 变更 / Changes

- `performance_feishu_contract.js` 为 outbox 快照增加受保护的配置 ID、配置版本和目标类型上下文；外部写入前会剥离内部上下文。
- `performance_feishu_delivery_service.js` 统一处理 UUID 幂等、回放、失败、待核对、显式重试和已批准映射版本复用。
- `feishu_client.js` 增加当前状态 upsert 与每日快照 batch append；读取飞书 App ID、Secret 和写入开关只发生在后端。
- `routes_performance.js` 增加性能投递列表、同步和重试 API；回执通过既有管理员确认路径完成。
- `app.js` 与性能监控 UI 展示最近投递、待核对和可重试状态，并在推广活动切换时使旧请求失效。
- `trusted_production_source_manifest.json`、受信来源门禁、部署清单和 `.gitattributes` 同步新增运行时服务及 LF 合同。

## API 与权限 / API And Permissions

- `GET /api/campaigns/:id/performance/feishu-deliveries`
- `POST /api/campaigns/:id/performance/feishu-sync`
- `POST /api/campaigns/:id/performance/feishu-deliveries/:deliveryId/retry`
- 读取遵循活动读取权限；写入、批准配置、重试和回执确认仍由活动负责人/组织管理员的既有权限边界控制，实际外部投递使用组织管理员批准的配置版本。
- 未配置或未启用 `FEISHU_PERFORMANCE_BITABLE_WRITE_ENABLED` 时，不发起外部写入，返回可审计的 CSV 降级结果。

## 范围边界 / Scope Boundary

本切片仍未实现 Phase 7B 的完整自动化闭环：Provider 定时采集、项目本地日“一天最多一次”不变量、小时级入站白名单、每日 02:00 夜间对账、死信/冲突处理、生产负载验证和 14 天连续观察。当前交付只提供人工触发的当前状态/每日快照投递、 durable outbox 回执、明确的待核对和重试路径。

This bounded slice does not claim the full Phase 7B automation loop: provider scheduling, the once-per-project-local-day invariant, hourly inbound allowlisting, the 02:00 nightly reconciliation job, dead-letter/conflict handling, production load validation, or 14-day observation remain open. The delivered surface is manual current-state/daily-snapshot delivery with durable outbox receipts, explicit reconciliation, and retry.
