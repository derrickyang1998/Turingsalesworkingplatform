## Delivery / 交付

- Conversation lists and details now share one bounded `run_summary`; each assistant message has a server-projected `run` with status, model, prompt/completion/total tokens, latency, and knowledge/Web reference counts. / 会话列表与详情现共享同一套有界 `run_summary`；每条 assistant 消息由服务端投影状态、模型、Prompt/Completion/Total Token、延迟及知识/Web 引用数量。
- Status semantics cover succeeded, degraded, failed, unknown, mixed, empty, and incomplete. A trailing user prompt overrides historical success as incomplete; malformed or non-object metadata becomes unknown. / 状态覆盖成功、降级、失败、未知、混合、空运行和未完成；尾部用户提示会覆盖历史成功并显示未完成，畸形或非对象元数据归为未知。
- Token values and accumulated totals remain nonnegative safe integers, and latency accepts only genuine integer milliseconds from zero through one hour. / Token 单项与累计值均保持非负安全整数，延迟只接受 0 至 1 小时内的真实整数毫秒值。

- List aggregation executes in SQLite and returns one row per selected conversation instead of loading every historical assistant message into Node.js. There is no schema migration or AI-generation/RAG behavior change. / 列表在 SQLite 内按选中会话聚合，不再把全部历史 assistant 消息载入 Node.js；无数据库迁移，也未改变 AI 生成或 RAG 行为。
