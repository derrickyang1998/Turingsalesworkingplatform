## Root Cause And Fix / 根因与修复

- The uploaded workbook was a valid OOXML XLSX. Both the local and production Python extractors could read its two worksheets and extract 1,102 characters. The filename and its `&` character were not the cause. / 用户上传的是有效 OOXML XLSX；本地与生产 Python 提取器均可读取两个工作表并提取 1,102 个字符，文件名及其中的 `&` 不是原因。
- The isolated ZIP inspector split every entry name on `/`. Standard zero-byte directory records such as `xl/` therefore produced a trailing empty component and were rejected as `Unsafe ZIP entry name`; the parent process converted this to the generic `Isolated parser failed` fallback. / 隔离 ZIP 检查器把所有条目名按 `/` 拆分，`xl/` 等标准零字节目录记录因此产生末尾空组件并被误判为不安全，父进程再将其归一为通用隔离解析失败降级。
- The inspector now removes exactly one terminal `/` only for a directory record, validates the resulting canonical path, and accepts the record only when compressed and uncompressed sizes are both zero. / 检查器现在仅对目录记录移除一个末尾 `/`，再校验规范路径，并且只有压缩前后尺寸均为零时才接受该目录记录。
- Absolute paths, drive paths, backslashes, empty intermediate components, `.`/`..`, symlinks, duplicate canonical file/directory collisions, non-zero directory records, archive bombs, entry limits, and expanded-size limits remain fail-closed. / 绝对路径、盘符路径、反斜杠、空中间组件、`.`/`..`、软链接、文件/目录规范名碰撞、非零目录记录、压缩炸弹及数量/展开尺寸限制继续失败关闭。
