## Objective / 目标

Replace the 15-minute scheduler bucket with a stable per-campaign local-day invariant. Repeated provider scheduler ticks for the same campaign on the same configured local day replay the existing run instead of consuming provider quota again; the next local day creates a new run. / 将 15 分钟调度桶改为稳定的“每项目本地日最多一次”不变量。同一活动在同一配置时区日期内的重复 tick 只重放既有运行，不重复消耗 Provider 配额；进入下一本地日后才创建新运行。

## Delivery And Scope / 交付与范围

- `performance_provider_collection_service` now derives `YYYY-MM-DD` with `Intl.DateTimeFormat` in a validated server-side time zone and uses `scheduled:<local-day>` as the scheduled idempotency key. / Provider 服务使用校验后的服务端时区生成本地日，并以 `scheduled:<local-day>` 作为定时运行幂等键。
- Default time zone is `Asia/Shanghai`; `PERFORMANCE_PROVIDER_TIME_ZONE` can override it. Invalid time zones fail service construction instead of silently scheduling against an unknown calendar. / 默认时区为 `Asia/Shanghai`，可由服务端环境配置；非法时区直接失败，不静默使用不确定日历。
- `PERFORMANCE_PROVIDER_SCHEDULER_INTERVAL_MS` is wired into both the service status and scheduler. Values outside 1 minute to 6 hours fall back to the 5-minute default. / 调度间隔同时接入服务状态和 scheduler，范围限定为 1 分钟至 6 小时，越界值回退为 5 分钟。
- Provider status now exposes `scheduler_interval_seconds`, `scheduler_time_zone`, `scheduled_local_day`, `scheduled_run_guard`, `last_scheduled_at`, and `last_scheduled_status`. / 状态接口新增调度间隔、时区、本地日、每日门禁和最近定时运行字段。
- No migration or UI replacement was introduced. Existing manual refresh, cooldown, rate/quota controls, immutable provider ledger, Feishu delivery, and performance dashboards remain intact. / 本版不新增迁移、不替换界面；人工刷新、冷却、限流/配额、不可变 Provider 账本、飞书投递和效果看板保持不变。
