## Feature Slice / 功能切片

**EN:** Route the existing demand-analysis endpoint through the permission-filtered, knowledge-first AI conversation service while preserving the current UI response contract. Web search remains explicitly controlled by `allow_web`; conversations, messages, references, usage, and summaries become auditable.

**中文：** 将现有需求分析接口接入按权限过滤、知识优先的统一 AI 对话服务，同时保持当前 UI 返回合同。联网搜索继续由 `allow_web` 显式控制；对话、消息、引用、用量和摘要可审计沉淀。

**EN:** Route PPT-outline generation through the same auditable AI service while preserving the current client-facing outline, fallback, research, knowledge-reference, and knowledge-archive contracts. Web search remains enabled by default for compatibility and can be explicitly disabled.

**中文：** 将 PPT 大纲生成接入同一可审计 AI 服务，同时保留现有客户版大纲、降级、联网调研、知识引用和知识归档合同。为保持兼容，联网默认开启，并可显式关闭。

**EN:** Route strategy generation through the same knowledge-first audit path. The prompt and business input now share one retrieval/web context, web search remains enabled by default with an explicit off switch, summary visibility can be overridden, and provider degradation is projected without breaking the current response.

**中文：** 将策略生成接入同一知识优先审计链。提示词与业务输入共用完整检索/联网上下文，联网保持默认开启并可显式关闭，摘要可见性可覆盖，模型降级在不破坏现有响应的前提下返回。

**EN:** Connect the latest M3 proposal workflow to `/api/ai/proposal-draft`. Knowledge and web references stay outside the editable draft, web search defaults off, proposal summaries are forced private, and only an explicit human confirmation archives the latest editor content as a final reusable artifact. Provider failure retains the deterministic local draft.

**中文：** 将最新 M3 方案流程接入 `/api/ai/proposal-draft`。知识与联网引用独立于可编辑草稿展示，联网默认关闭，方案摘要强制个人私有；只有人工明确确认时才把编辑器中的最新内容归档为可复用最终方案，模型失败时保留本地基础草稿。

**EN:** Archive successful `POST /api/demand/parse-file` runs as private `requirement_sheet` knowledge entries. The route preserves the legacy response and adds `knowledge.archivedEntryId`, deduplicates by an owner-scoped digest of user ID plus file SHA-256, stores operational quality and retention metadata, and completes archive ingest plus upload admission atomically in one immediate SQLite transaction.

**中文：** 将成功的 `POST /api/demand/parse-file` 解析结果归档为私有 `requirement_sheet` 知识条目。接口保留既有响应，仅新增 `knowledge.archivedEntryId`；去重改为“用户 ID + 文件 SHA-256”的 owner-scoped digest，metadata 只保留质量与留存等操作事实，并把知识归档写入与上传 admission 完成合并到同一个 immediate SQLite 事务中原子执行。

**EN:** Long Unicode demand summaries now truncate by code point instead of UTF-16 units, so astral characters are preserved and knowledge validation no longer fails on isolated surrogates.

**中文：** 长 Unicode 需求摘要现在按 code point 而不是 UTF-16 单元截断，astral character 不会再被拆断，知识校验也不会再因为孤立 surrogate 而失败。

**EN:** Task 6A adds an authenticated campaign demand plus human-confirmed proposal mutation. One immediate SQLite transaction creates real demand and proposal IDs, their knowledge archives, business/archive links, activity evidence, and replay-safe idempotency evidence. M3 freezes its confirmation attempt before awaiting, rejects stale completions after reset/navigation/edit, and hands the confirmed real IDs plus `demand_entry_id` to M4.

**中文：** Task 6A 增加受认证的活动需求加人工确认方案变更：同一个 immediate SQLite 事务创建真实需求和方案 ID、各自知识归档、业务/归档链接、活动证据及可安全重放的幂等证据。M3 在等待确认前冻结本次尝试，重置/导航/编辑后的陈旧完成不得恢复 UI，并将确认后的真实 ID 与 `demand_entry_id` 交给 M4。

## Contracts / 合同

- Retrieval uses the user prompt and uploaded demand content, not the JSON formatting instructions. / 检索使用用户提示和上传需求内容，不使用 JSON 格式指令污染检索。
- Accessible team knowledge can be cited; another user's private knowledge cannot enter the model context or references. / 可访问的团队知识可引用，其他用户私有知识不得进入模型上下文或引用。
- `allow_web=false` performs zero web-provider calls and stores zero web references. / `allow_web=false` 时联网 provider 调用和联网引用均为零。
- Existing `analysis`, `fallback`, and `warning` fields remain; additive `ai` data exposes the audit identifiers and references. / 保留既有字段，并以新增 `ai` 投影返回审计标识和引用。
- Provider degradation and invalid JSON preserve a safe provider reason when one exists. / 模型降级或 JSON 无效时优先保留安全的 provider 原因。
- PPT output preserves `outline`, `knowledge_references`, `research`, `fallback`, and `warning`; additive `ai` data exposes the persisted run. / PPT 返回保留既有字段，仅新增 `ai` 审计投影。
- PPT web search is enabled by default; explicit `allow_web=false` performs zero provider calls and stores zero web references. / PPT 联网默认开启；显式关闭时 provider 调用和联网引用均为零。
- PPT knowledge archival stores the exact audited knowledge IDs and AI conversation/message linkage without duplicate usage telemetry. / PPT 知识归档保存精确审计引用及 AI 会话/消息关联，且不重复计数知识用量。
- Strategy retrieval and web queries include both the prompt and business input; explicit `allow_web=false` makes zero web-provider calls and stores zero web references. / 策略检索与联网查询同时包含提示词和业务输入；显式关闭联网时调用和联网引用均为零。
- Strategy summaries default to team visibility and preserve an explicit private override. Provider degradation maps to `fallback` and a safe `warning`. / 策略摘要默认团队可见并保留显式私有覆盖；模型降级映射到 `fallback` 和安全 `warning`。
- Strategy `knowledge_limit` accepts only integer values or pure digit strings from 1 through 100; invalid values fall back to 8. / 策略 `knowledge_limit` 仅接受 1 至 100 的整数或纯数字字符串，无效值回退为 8。
- Proposal retrieval uses demand and template context without generation instructions; web search defaults off and proposal chat summaries are always private. / 方案检索只使用需求和模板上下文，不混入生成指令；联网默认关闭，方案对话摘要始终为个人私有。
- A draft is never treated as a confirmed artifact. Confirmation archives the current edited content through the governed customer path or the legacy proposal path when no customer is attached. / 草稿不得视为确认方案；确认操作归档当前编辑内容，有客户时走受治理客户接口，无客户时走既有方案接口。
- Generation captures its own customer context, clears stale context on reset/navigation, and ignores superseded asynchronous responses. / 每次生成冻结自己的客户上下文，重置或重新进入页面时清除旧上下文，并忽略已被新请求替代的异步响应。
- Successful demand parsing archives one private `requirement_sheet` knowledge entry with `source_type='demand_file_upload'`, `business_type='demand'`, and additive `knowledge.archivedEntryId`. / 成功的需求解析会归档 1 条私有 `requirement_sheet` 知识记录，固定使用 `source_type='demand_file_upload'`、`business_type='demand'`，并附加返回 `knowledge.archivedEntryId`。
- Same owner plus same file bytes reuse one archive entry even if the filename changes; another owner uploading the same bytes gets a different private entry. / 同一归属人上传相同文件字节时即使文件名变化也复用同一归档条目；其他归属人上传相同字节则得到不同的私有条目。
- Demand archive metadata is limited to filename, MIME, size, raw file SHA-256, parser/fallback/OCR/warning state, `quality_state`, `retention_class`, and `citation_count`. / 需求归档 metadata 只保留文件名、MIME、大小、原始文件 SHA-256、parser/fallback/OCR/warning 状态，以及 `quality_state`、`retention_class` 和 `citation_count`。
- `authority.readFresh(db)`, knowledge ingest, and upload-admission completion run in one immediate SQLite transaction; archive failure prevents admission completion. / `authority.readFresh(db)`、知识写入与上传 admission 完成运行在同一个 immediate SQLite 事务中；若归档失败，admission 不会完成。
- Demand archive summary truncation counts code points so long Unicode text cannot split astral characters into isolated surrogates. / 需求归档摘要截断按 code point 计数，长 Unicode 文本不会再把 astral character 拆成孤立 surrogate。
