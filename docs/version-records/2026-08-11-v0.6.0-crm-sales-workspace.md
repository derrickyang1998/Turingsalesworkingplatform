## Cutover Contract / 切换合同

- Cleanup-control replay accepts only the canonical absent/enabled topologies, idempotently resolves the one exact `.restore.next` residue, validates all control-path parents before mutation, and binds effective PID 1 fragment/Names/DropInPaths across every systemd search root. Public watchdog deadlines are operation-specific: 120 seconds for initial cutover and 7,200 seconds for accepted finalization plus rollback/resume; identity is revalidated before each public link swap and disarm. / 清理控制回放仅接受两种 canonical topology，并在首次变更前验证父链及 PID 1 实际配置；公网 watchdog 的操作专属窗口为初始切换 120 秒、接受态 finalization 与回滚/恢复 7,200 秒，公网切换及解除前均复核 active identity。
- External state now has five targets: four exact root-owned links for environment, database, uploads, and temporary files, plus the direct root-only `PPT_CACHE_DIR=/var/lib/turingmarket/ppt-cache` directory. The PPT cache is not a release-tree symlink. / 外置状态现有五个目标：环境、数据库、上传和临时文件使用四个精确 root 所有软链接，PPT 缓存则直接使用 root-only 目录；PPT 缓存不是发布树软链接。
- A first-install backup records `ppt-cache.absent`. Only after PM2 writers stop does cutover create an empty `root:root 0700` cache. Pre-mutation recovery removes it only while empty; rollback preserves the recorded absent origin only when the restored cache is also empty. / 首次安装备份记录 `ppt-cache.absent`；只有 PM2 停写后才创建空的 `root:root 0700` 缓存。预变更恢复仅在其仍为空时删除，回滚也只在恢复缓存为空时恢复 absent 起源。

- Ordering is fixed: enter all-traffic maintenance, drain parser admissions/spool/units/cgroup, stop and quiesce PM2 plus SQLite, drain the parser again, prepare the PPT cache, snapshot the database/cache/parser as one verified unit, exchange code, install the parser, start the candidate, and run acceptance. / 顺序固定为全流量维护、解析器 admission/spool/unit/cgroup 排空、PM2 与 SQLite 停写静默、再次排空解析器、准备 PPT 缓存、数据库/缓存/解析器同单元快照、交换代码、安装解析器、启动候选并验收。
