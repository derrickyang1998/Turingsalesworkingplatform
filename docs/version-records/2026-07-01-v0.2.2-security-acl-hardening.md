# v0.2.2 Security ACL Hardening

Date: 2026-07-01

## Goal

Close the final review blockers for the AI knowledge-base rollout before marking the platform ready: remove static default credentials, enforce CRM record ownership checks, and make private CRM knowledge follow the business owner.

## Changes

- Removed tracked and UI-visible static default password references from login UI, deployment docs, migration notes, legacy smoke scripts, and old server fallback files.
- Changed admin user creation and password reset APIs to generate one-time temporary passwords when no explicit password is provided.
- Changed database seeding so admin and team users do not share one seed password.
- Added `crm_access_service` for shared CRM ownership checks.
- Enforced CRM access checks for customer detail/update/delete/return, lead update/convert, opportunity create/update/delete, customer activity, and public-pool claim result handling.
- Kept public-pool customer detail readable while blocking opportunity mutation/delete before claim.
- Filtered non-admin dashboard customer activity to records owned by or assigned to the current user.
- Changed CRM private knowledge archival to use lead/customer/opportunity business owners instead of the actor who performed the operation.

## Verification

- Added `security_and_crm_access.test.js` covering:
  - public files and admin APIs do not expose the legacy default password
  - cross-user CRM customer/opportunity access is rejected
  - private customer listing cannot be bypassed with `is_public=0`
  - public-pool customer visibility does not allow opportunity mutation
  - seeded admin and team users do not share one default password
  - CRM private knowledge archives use the business owner
- Local `node --check` passed for 30 JavaScript files.
- Local `npm test` passed: 16/16 tests.
- Local `npm audit --json` reported 0 vulnerabilities.
- `git diff --check` reported no whitespace errors.
- Secret scan found only detector regex false positives in the test and Obsidian sensitive-content scanner.

## Deployment Notes

- Production admin/team passwords must be rotated away from the legacy password before final completion.
- `TAVILY_API_KEY` remains optional; if absent, AI chat continues in knowledge-only mode.
