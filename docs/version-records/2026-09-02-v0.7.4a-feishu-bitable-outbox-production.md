# v0.7.4a Feishu Bitable Outbox Production Record

## Scope / 范围

- Implementation commit: `feedfba`; release-fixture correction: `5d4c683`.
- Campaign-scoped durable Bitable delivery receipts are now stored in `feishu_bitable_outbox`. Each receipt binds organization, campaign, actor, bare UUID, immutable payload snapshot, record count, state and safe completion metadata.
- A repeated UUID with the same payload returns its prior receipt and does not send another provider request. A mismatched UUID replay is rejected.
- Ambiguous provider/local completion outcomes remain `pending`; they are not automatically resent or terminalized. Only a campaign Owner or organization administrator can reconcile a pending receipt with verified, unique remote record IDs.
- Database triggers prevent terminal update/delete, reject `INSERT OR REPLACE` receipt replacement even with recursive triggers disabled, and reject duplicate remote record IDs. CSV fallback and the existing Webhook path remain compatible.
