# v0.9.25 Organization Monthly Shared AI Quota Implementation Plan

## Delivery Cadence Override / 交付节奏覆盖

- **One feature, one production release / 一功能一上线：** Finish one independently usable feature, complete its focused verification and independent review, create a verified rollback point, and deploy it to production in the same development round. Do not wait for the rest of the phase. / 每完成一个可独立使用的功能，完成定向验证与一次独立审查、创建可校验回滚点后，在同一开发轮立即部署生产，不等待本阶段其他功能。
- **Focused tests by default / 默认轻量定向测试：** Run only the exact affected unit, API, contract, syntax, secret, and diff checks. UI work adds only the changed desktop/mobile journey. / 默认只运行精确受影响的单元、API、契约、语法、密钥和差异检查；UI 改动只增加本次旅程的桌面与移动端检查。
- **Risk-based expansion / 按风险扩展：** Full regression is reserved for phase closeout or changes involving schema, authentication/authorization, tenant authority, shared release infrastructure, or real third-party writes. Even then, add only the gates required by that risk boundary rather than unrelated suites. / 完整回归仅用于阶段收口，或涉及数据库结构、认证/授权、租户权威、共享发布基础设施、真实第三方写入的改动；即使触发，也只增加该风险边界所需门禁，不追加无关套件。
- **Production acceptance is mandatory / 线上验收不可省略：** Every release still requires backup verification, health/login/feature smoke checks, and rollback on a mandatory failure. / 每个版本仍必须验证备份，完成健康、登录和本功能线上冒烟；强制项失败立即停止或回滚。

**Current slice classification / 当前切片分类：** `v0.9.25` changes schema and central AI admission, so it keeps only the bounded migration, quota, authorization, release-contract, and online reversible acceptance gates. It does not run unrelated CRM, influencer, proposal, PPT, or full browser suites. / `v0.9.25` 涉及数据库结构和中央 AI 准入，因此仅保留有界的迁移、配额、授权、发布契约及线上可逆验收门禁；不运行无关的 CRM、网红、方案、PPT 或完整浏览器套件。

1. Add schema v29 append-only organization quota policy with unlimited backfill and new-organization default.
2. Add UTC month usage aggregation and organization quota projection to the central quota service.
3. Enforce organization then user quota at every existing AI admission call and persist scoped denial audits.
4. Add member read and platform-admin versioned update endpoints with exact request validation.
5. Project monthly quota into the Admin organization directory and add compact edit/save controls.
6. Update migration sanitizer/trusted bundle/deploy inventories to schema v29.
7. Run only affected migration, quota, auth, route, directory/UI and release-gate tests plus syntax, focused secret, and diff checks; do not run unrelated full suites.
8. Obtain one independent code review, back up production, deploy in this same development round, and run reversible deny/restore online acceptance before starting the next feature.
9. Update CHANGELOG, bilingual roadmap, progress dashboard, version record, archive, Obsidian, and GitHub.

## Minimal Change Guard

- Do not alter CRM, AI chat, knowledge, proposal, PPT, influencer, or performance-report layouts.
- Do not change existing personal quota storage or API behavior.
- Do not call an external LLM during acceptance; prove denial before provider dispatch and exact policy restoration.
