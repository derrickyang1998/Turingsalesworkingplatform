# AI Token Quota Admission Implementation Plan / AI Token 配额准入实施计划

> Deliver one independently useful function, run affected checks and one independent review, then create a verified backup and deploy immediately. / 每轮交付一个可独立使用的功能，执行受影响验证和一次独立审查后，创建可验证备份并立即上线。

**Goal / 目标:** Enforce the existing per-user AI Token quota on the server for every production AI provider path, expose its organization-owned usage state to administrators, and make quota changes auditable. / 在所有生产 AI Provider 路径统一执行现有用户级 AI Token 配额，并向管理员展示按组织归属的用量状态，使配额变更可审计。

**Architecture / 架构:** A single quota service reads the live user, active organization membership, and schema-v26 organization-owned token ledger. Provider calls are admitted only after that decision; completed linked idempotency replays remain readable before a new admission check. Successful AI output and trusted token accounting commit together where the AI service owns persistence. / 单一配额服务读取实时用户、有效组织成员关系和 schema v26 的组织归属 Token 台账；只有准入通过才调用 Provider，已完成的关联幂等回放仍优先返回。由 AI 服务负责持久化的成功输出与可信 Token 计量在同一事务提交。

## In Scope / 本轮范围

- Add `ai_quota_service` with live admission, tenant-scoped lifetime usage projection, fail-closed accounting, quota update, and bounded audit records.
- Apply admission to legacy chat, linked chat, one-shot demand/proposal/PPT generation, strategy generation, performance AI review/content analysis, and brand enrichment.
- Treat ordinary-user quota `0` as AI disabled; keep active platform administrators explicitly exempt.
- Add a dedicated administrator quota-update API and show per-organization used/limit/remaining/status plus an editable user limit in the existing Admin Control Room.
- Preserve the current product shell, CRM, M3/M4, knowledge/RAG, proposal/report, and frozen PPT behavior.

## Out Of Scope / 本轮不做

- No plan catalog, module entitlement catalog, subscription expiry, billing, organization-shared monthly quota, pricing, or payment settlement.
- No persistent concurrency reservation. Concurrent admitted requests may finish above the soft limit; subsequent requests are denied from the updated trusted ledger.
- No schema migration, vector database, broad UI redesign, real external delivery, or PPT renderer change.

## Fixed Decisions / 固定决策

- Quota period / 配额周期：`legacy_lifetime`.
- Ordinary status / 普通用户状态：`active`, `exhausted`, or `disabled`.
- Platform administrator status / 平台管理员状态：`exempt`.
- Failure policy / 失败策略：missing live policy or untrusted ledger returns `503`; disabled/exhausted returns typed `429`; trusted usage persistence failure returns `503` and cannot return a successful AI result.
- Final future access chain remains `role permission ∩ plan entitlement ∩ quota`; this release implements only the existing quota-admission term. / 未来完整准入链仍为“角色权限 ∩ 套餐权益 ∩ 配额”，本版只完成现有配额准入项。

## Acceptance / 验收

- Client/JWT role or quota fields cannot override the live SQLite user, membership, or organization-owned ledger.
- Organization A usage never consumes organization B quota; zero and exhausted quotas stop provider I/O and create bounded denial audits.
- Completed linked idempotency responses replay without another provider call even after quota is consumed.
- Token accounting failure cannot persist or return a successful assistant result.
- Only an active platform administrator can change quota; the quota and its audit commit atomically.
- Focused service, route, AI/RAG, proposal/PPT, performance, Admin UI, syntax, source-inventory, secret, and diff checks pass; one independent reviewer approves; the verified backup, guarded production deployment, and focused online acceptance pass.
