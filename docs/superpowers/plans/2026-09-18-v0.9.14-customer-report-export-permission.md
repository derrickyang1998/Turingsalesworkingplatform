# v0.9.14 Customer Report Export Permission / 客户复盘报告导出权限

## Goal / 目标

Ship one bounded Phase 8 permission slice: require the live organization-scoped
`campaign.customer_report.export` action before delivering an existing sealed
customer report as HTML or PPTX.

交付一个独立的 Phase 8 权限切片：现有已封存客户复盘报告在导出 HTML 或
PPTX 前，必须通过实时组织范围的 `campaign.customer_report.export` 权限。

## Product Contract / 产品契约

- Writable company owners, organization administrators, managers, and members
  may pass the named permission gate.
- Read-only and platform-admin-only identities may not export.
- The named permission is necessary but not sufficient. Existing campaign and
  snapshot ownership checks in the delivery service remain authoritative.
- Denied and completed delivery attempts write bounded audit evidence. Audit
  failure is fail-closed before response headers or report bytes leave the
  server.
- Preview, sealing, snapshot list/detail, PPT rendering, report content,
  database schema, and external Feishu writes are unchanged.

- 可写的企业所有者、组织管理员、经理和成员可通过该权限门禁。
- 只读账号和仅平台管理员身份不得导出。
- 权限仅是必要条件；交付服务中现有 Campaign 与快照归属校验继续生效。
- 拒绝与完成的交付均写入有界审计；审计不可用时，在响应头或报告字节发出前
  失败关闭。
- 预览、封存、快照列表/详情、PPT 渲染、报告内容、数据库结构及飞书外部写入
  均不变。

## Test-First Tasks / 测试优先任务

1. Add failing policy tests for writable, read-only, platform-only, and malformed
   organization scopes.
2. Add failing route tests proving both delivery endpoints authorize before the
   delivery service, emit bounded audit evidence, and never leak headers/bytes
   when denied or when audit storage fails.
3. Add failing login and `/api/auth/me` projection assertions.
4. Add failing frontend contract checks for hidden controls and direct-call
   guards.
5. Implement the smallest runtime wiring, run affected authorization tests,
   obtain an independent review, back up production, deploy, and perform focused
   online acceptance.

## Acceptance / 验收

- Requests that reach the named permission gate and are denied return
  `403 CUSTOMER_REPORT_EXPORT_FORBIDDEN`, do not invoke the delivery service,
  and emit no attachment headers or bytes. Read-only `POST` requests remain
  subject to the earlier platform-wide `403 ORGANIZATION_READ_ONLY` guard.
- Audit failure returns `503 CUSTOMER_REPORT_EXPORT_AUDIT_UNAVAILABLE` before
  attachment headers or bytes are sent.
- Allowed HTML and PPTX delivery retain their existing formats and service-level
  custody checks.
- The current UI, customer report data contract, and frozen PPT renderer remain
  intact.
