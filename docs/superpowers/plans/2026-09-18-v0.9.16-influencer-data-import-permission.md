# v0.9.16 Influencer Data Import Permission / 网红数据导入权限

## Goal / 目标

Ship one bounded Phase 8 permission slice: require the live organization-scoped
`influencer.data.import` action for manual creation, JSON import, and multipart
preview/import without changing the accepted M4 workflow.

交付一个独立的 Phase 8 权限切片：手工新增、JSON 导入和 multipart 预览/导入
均必须通过实时组织范围的 `influencer.data.import` 权限，同时保持已验收的 M4
流程不变。

## Product Contract / 产品契约

- Writable company owners, organization administrators, managers, and members
  may import influencer data. Read-only and platform-admin-only identities may
  not import.
- Denied requests are rejected before JSON or multipart body parsing. Multipart
  requests reauthorize against fresh identity state before persistence.
- Preview, completed import, and denial events write bounded audit evidence;
  rows, file names, source contents, and mappings are never stored in the audit.
- Business rows, knowledge archival, parser admission, and completed audit
  commit atomically where the existing workflow supports them. Audit failure is
  fail-closed.
- The template remains downloadable without import permission. Import controls
  are hidden and disabled, and direct client calls fail before network access.
- Existing export, search, saved views, Feishu, collaboration ordering, schema,
  AI/knowledge, proposal, frozen PPT renderer, and current product shell remain
  unchanged.
- The influencer inventory remains a shared global dataset. Organization row
  ownership and tenant isolation require a separate schema release.

- 可写的企业所有者、组织管理员、经理和成员可导入网红数据；只读账号和仅平台
  管理员身份不得导入。
- 拒绝发生在 JSON 或 multipart 请求体解析前；multipart 在持久化前再次读取
  最新身份并授权。
- 预览、成功导入和拒绝均写入有界审计，不记录业务行、文件名、源内容或字段映射。
- 在既有流程支持范围内，业务数据、知识归档、解析准入与成功审计原子提交；审计
  不可用时失败关闭。
- 无导入权限时仍可下载模板；导入控件隐藏且禁用，直接调用在发起网络请求前拒绝。
- 既有导出、搜索、保存视图、飞书、合作下单、schema、AI/知识库、方案、冻结 PPT
  渲染器及产品壳层保持不变。
- 网红主表仍是全局共享数据；组织行归属与租户隔离留在独立 schema 版本。

## Focused Delivery / 定向交付

1. Test the named policy and projected login actions.
2. Test early denial, fresh multipart reauthorization, bounded audit, replay,
   and transactional rollback.
3. Test permission-aware controls while preserving template access and the
   existing end-to-end M4 administrator journey.
4. Run syntax, diff, and focused secret checks plus one independent review.
5. Create a verified backup, deploy immediately, and run focused production
   login, permission, preview, audit, health, and logout acceptance.

## Out Of Scope / 非本版范围

No `org_id` migration, row-level tenancy, entitlement/quota work, real Feishu
write changes, collaboration-order changes, PPT changes, or visual redesign.

不包含 `org_id` 迁移、行级租户隔离、套餐/配额、真实飞书写入改造、合作下单改造、
PPT 改造或视觉重设计。
