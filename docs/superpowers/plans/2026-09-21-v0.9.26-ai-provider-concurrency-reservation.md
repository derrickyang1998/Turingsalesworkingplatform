# v0.9.26 Durable AI Provider Concurrency Reservation Implementation Plan

## Delivery Cadence Override / 交付节奏覆盖

- **One feature, one production release / 一功能一上线：** Complete this independently usable concurrency boundary, run focused checks and one independent review, create a verified rollback point, and deploy it immediately. / 完成本次可独立使用的并发边界后，执行定向检查和一次独立审查，创建可验证回滚点并立即上线。
- **Focused tests by default / 默认轻量定向测试：** Run only migration, reservation concurrency, permission, API/UI contract, provider-inventory, syntax, secret, and diff checks. / 默认只运行迁移、预留并发、权限、API/UI 契约、Provider 清单、语法、密钥与差异检查。
- **Risk-bounded expansion / 风险边界扩展：** Because schema and central Provider admission change, retain migration replay/integrity and all affected AI-path gates; do not run unrelated CRM, influencer, Feishu, or full browser suites. / 因数据库结构和中央 Provider 准入发生变化，保留迁移重放/完整性与全部受影响 AI 路径门禁；不运行无关 CRM、网红、飞书或完整浏览器套件。
- **Production acceptance remains mandatory / 线上验收不可省略：** Verify backup, health, login, typed rejection, restoration, and zero active reservations. / 必须验证备份、健康、登录、类型化拒绝、策略恢复及活跃预留归零。

## Tasks / 任务

1. Add schema v30 append-only organization concurrency policy, durable reservation state, event ledger, indexes, guards, and default policy backfill.
2. Add a concurrency service that atomically reclaims expired reservations, acquires capacity, validates fencing ownership, records dispatch/provider events, releases terminal work, projects status, and updates policy with optimistic version checks.
3. Wire one reservation around every logical external AI operation while preserving completed idempotent replay and preventing concurrency errors from falling back to false success.
4. Add member read and platform-admin exact-body update APIs; project aggregate concurrency into the existing organization directory.
5. Extend the existing AI quota cell with compact active/limit/status controls without adding navigation, pages, cards, or columns.
6. Update migration registries, sanitizer/trusted-source manifests, deployment inventory, and target schema to v30.
7. Run RED/GREEN focused tests for migration, multi-connection last-slot competition, expiry/fencing, authorization, route validation, compact UI, and Provider path inventory.
8. Obtain an independent code review and fix every release-blocking finding.
9. Commit and push GitHub, verify a production backup, deploy in the same round, and execute reversible limit-one deny/release/restore acceptance.
10. Update CHANGELOG, bilingual roadmap/progress dashboard, version record, external archive, Obsidian archive, and GitHub evidence.

## Minimal Change Guard

- Do not change CRM, influencer, Feishu, knowledge-base, proposal editor, or PPT renderer layouts/behavior.
- Do not add a queue, background worker, force-release control, pricing, billing, or Token estimation.
- Do not make administrator AI requests exempt from concurrency.
- Do not expose reservation identity, user/job detail, prompts, responses, or fencing tokens in the UI or audit logs.
- Do not call a real external Provider for the rejection acceptance; prove denial before dispatch, then restore the exact original policy.
