# AI Conversation Tenant Ownership Implementation Plan / AI 对话租户归属实施计划

> Execute as one independently useful production release. Use exact affected tests, one independent review, then backup and deploy immediately. / 作为一个可独立使用的生产版本执行；仅跑精确受影响测试和一次独立审查，随后立即备份上线。

**Goal:** Ship schema v25 and enforce immutable organization ownership for AI conversations without changing the accepted UI or frozen PPT output. / 发布 schema v25，为 AI 对话建立不可变组织归属，不修改已验收 UI 与冻结 PPT 输出。

**Architecture:** Backfill `ai_conversations.org_id` from authoritative Campaign, archived-knowledge, and reference evidence; reject ambiguity; use the unique legacy default only when no evidence exists. Thread server-owned organization context through create, continue, read, Campaign-linked persistence, and knowledge promotion. / 从 Campaign、归档知识和引用证据回填 `ai_conversations.org_id`，歧义即失败；无证据时仅使用唯一历史默认组织。将服务端组织上下文贯穿创建、续聊、读取、Campaign 关联持久化和知识沉淀。

**Tech Stack:** Node.js 20, Express 5, SQLite/better-sqlite3, Node test runner, guarded PowerShell deployment.

**Spec:** `docs/superpowers/specs/2026-09-19-ai-conversation-tenant-ownership-design.md`

## Constraints / 约束

- Preserve all pre-v25 AI data and current API/UI response contracts.
- Never trust organization ownership from request payloads.
- Keep platform-admin global visibility only in audited list/detail surfaces.
- Do not modify the frozen PPT renderer or unrelated product modules.
- Use focused schema/runtime/release tests; defer broad regression to Phase 8 closeout.
