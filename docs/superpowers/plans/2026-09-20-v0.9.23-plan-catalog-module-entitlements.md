# v0.9.23 Plan Catalog And Module Entitlements Implementation Plan

**Goal / 目标:** Ship the authoritative plan catalog and organization module entitlement contract as one production release without changing the latest product shell or frozen PPT implementation.

## Scope / 范围

1. Add schema v27 immutable catalog, append-only assignment history, deterministic `legacy_full` backfill, and new-organization default assignment.
2. Add a plan-entitlement service and exact admin/member routes with atomic audited assignment.
3. Intersect all seven existing organization-scoped module/action policies with the active organization plan in the central authorization service.
4. Project plan summaries into organization governance and add a compact Admin organization plan control.
5. Update migration/release inventories and version records without touching unrelated upload-sandbox work or frozen `ppt.js`.

## Verification / 验证

- TDD: record focused RED evidence before implementation.
- Run exact migration, plan service/route, module permission, organization governance, auth projection, and changed UI contract tests.
- Because this slice changes schema and authorization, also run migration replay/integrity, production-shaped sanitized rehearsal, changed JavaScript syntax, focused secret scan, `git diff --check`, and one independent review.
- Do not run unrelated heavy full suites.
- After approval: push, create and verify production backup, deploy immediately, then verify health, schema v27, login/me projection, catalog/member read, one reversible organization plan round trip, audit, rollback target, PM2/Nginx, and frozen PPT hash.

## Release Exclusions / 发布排除

Subscription expiry, billing, pricing, shared organization quota, persistent concurrency reservations, AI-plan gating, catalog editing, and broad interface redesign remain separate feature releases.
