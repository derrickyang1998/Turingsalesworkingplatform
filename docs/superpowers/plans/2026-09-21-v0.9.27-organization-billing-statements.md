# v0.9.27 Organization Billing Policy And Monthly Statements Implementation Plan

## Delivery Cadence Override / 交付节奏覆盖

- **One feature, one production release / 一功能一上线：** Deliver only the independently useful billing-policy and monthly-statement slice, then deploy it in the same round. / 本轮只交付可独立使用的计费策略与月度账单切片，完成后同轮上线。
- **Focused tests by default / 默认轻量定向测试：** Run only billing migration, calculation, tenant permission, API/UI contract, syntax, secret, and diff checks. / 默认只运行账单迁移、计算、租户权限、API/UI 契约、语法、密钥与差异检查。
- **Risk-bounded expansion / 风险边界扩展：** Because this slice adds schema v31 and financial calculations, retain migration replay/restore, immutable-ledger, safe-integer, and authorization gates; do not run unrelated CRM, influencer, Feishu, PPT, or full browser suites. / 因本切片新增 schema v31 和财务计算，保留迁移重放/恢复、不可变台账、安全整数及授权门禁；不运行无关 CRM、网红、飞书、PPT 或完整浏览器套件。
- **Production acceptance remains mandatory / 线上验收不可省略：** Verify backups, health, dedicated internal-session identity, own-tenant/admin reads, denial boundaries, formula evidence, restoration, and zero production acceptance statements. Never use `derrick` or credential rotation for smoke tests. / 必须验证备份、健康、专用内部会话身份、本组织/管理员读取、拒绝边界、公式证据、策略恢复及生产库不遗留验收账单；严禁使用 `derrick` 或凭据轮换进行冒烟。

## Tasks / 任务

1. Add schema v31 append-only organization billing policies and immutable monthly statements with default-disabled backfill, indexes, triggers, and manifest contracts.
2. Add a billing service that resolves month-effective policy, sums immutable organization Token usage, calculates cents with `BigInt`, projects estimates, enforces tenant roles, appends policies with optimistic versioning, and closes one digest-bound statement atomically.
3. Add exact-body own-organization and platform-admin APIs with typed errors and bounded privileged-read/change/close audit events.
4. Project current-month billing into the existing organization directory and add a compact Billing column/editor without changing navigation or unrelated modules.
5. Register migration v31 in the database, sanitizer, trusted-source, schema gate, deployment inventory, and target schema contracts.
6. Add the root-only billing acceptance verifier, close a real statement only on an isolated production clone, and bind its canonical SHA-256 evidence into deployment acceptance facts before cutover.
7. Run RED/GREEN focused tests for migration immutability/defaults, month resolution, integer rounding/overflow, role/tenant denial, idempotent close, audit atomicity, exact API bodies, compact UI, acceptance verifier, and release inventory.
8. Obtain one independent code-review approval and fix every HIGH/CRITICAL or release-blocking finding.
9. Commit and push GitHub, verify a main production backup plus a separate pre-provision backup, provision or exactly reuse the fail-closed `release-smoke` identity, deploy immediately, and run health/internal-session/feature acceptance without using `derrick` or any historical password.
10. Update CHANGELOG, bilingual roadmap/progress dashboard, version record, external archive, Obsidian archive, and GitHub evidence.

## Minimal Change Guard

- Do not change CRM, influencer, Feishu, knowledge-base, proposal, PPT, or content-performance behavior.
- Do not add a payment gateway, invoice generation, tax logic, refunds, credits, manual adjustments, or dynamic plan catalog editing.
- Do not derive commercial prices from existing plans or provider costs; the default remains disabled and zero until an administrator explicitly configures a policy.
- Do not use floating-point arithmetic for money and do not read usage totals from the browser.
- Do not prorate partial months. Bill every immutable organization-owned usage row, including rows created by a platform administrator in that organization context.
- Do not let an administrator rewrite history, close the current month, bypass optimistic versions, or delete a statement.
- Do not expose another organization's billing projection to managers, members, read-only users, inactive users, or unaffiliated callers.
- Do not modify an existing release-smoke identity, recover credentials after a failed login, or use `derrick` for release acceptance. Any identity mismatch must fail closed.
