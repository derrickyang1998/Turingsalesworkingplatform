# Knowledge Tenant Isolation Implementation Plan / 知识库租户隔离实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Complete one task, review it, then continue without waiting for user confirmation.

**Goal:** Ship schema v24 and enforce current-organization knowledge isolation across ingestion, search, AI RAG, category counts, similar lookup, and usage updates. / 发布 schema v24，并在知识入库、搜索、AI RAG、分类、相似检索及使用计数中强制当前组织隔离。

**Architecture:** Add immutable `knowledge_entries.org_id`, deterministically backfill from custody/organization-business/default facts, then thread server-owned organization context through every non-Campaign knowledge path. Mutable membership is not historical ownership evidence. Keep platform-admin knowledge audit global but force AI/RAG to the active organization. / 为知识条目增加不可变 `org_id`，基于保管/组织业务关联/默认组织事实确定性回填，并将服务端组织上下文贯穿所有非 Campaign 知识路径；可变成员关系不作为历史归属依据。管理员知识审计保持全局，AI/RAG 必须限定当前组织。

**Tech Stack:** Node.js 20, Express 5, SQLite/better-sqlite3, Node test runner, guarded PowerShell deployment.

**Spec:** `docs/superpowers/specs/2026-09-18-knowledge-tenant-isolation-design.md`

## Global Constraints

- Preserve the accepted latest UI, AI chat flow, proposal/report behavior, influencer workflow, and frozen PPT bytes.
- Never trust organization IDs from request bodies; use authentication, Campaign, or organization-custody facts only.
- Preserve all existing knowledge/chunk/FTS IDs and pre-v24 values; migration must fail closed on ambiguous custody or projection drift.
- Use exact affected tests plus schema safety gates; do not run unrelated full suites before this independent release.
- No production business-row mutation during acceptance except the schema migration and reversible temporary fixtures.
