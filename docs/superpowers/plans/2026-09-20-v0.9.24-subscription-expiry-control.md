# v0.9.24 Subscription Expiry Control Implementation Plan

**Goal / 目标:** Ship server-enforced organization subscription expiry as one production release while preserving the latest product shell and frozen PPT implementation.

## Scope / 范围

1. Add schema v28 append-only subscription terms, deterministic perpetual backfill, strict canonical expiry constraints, and new-organization default term.
2. Add a subscription-expiry service and exact member/admin routes with compare-and-swap updates and atomic audit.
3. Intersect all seven existing organization-scoped module/action policies with the live subscription state in the central authorization service.
4. Project subscription status into organization governance and add a compact Admin expiry control.
5. Update the schema/release inventories, deployment bundle, changelog, bilingual roadmap, progress dashboard, version archive, Obsidian copy, and GitHub record.

## Test-First Sequence / 测试先行顺序

1. Add migration tests for empty/existing databases, deterministic backfill, new-organization defaults, canonical dates, append-only history, contiguous versions, and partial-object rejection.
2. Add service tests for membership/admin boundaries, projections, compare-and-swap, idempotence, audit atomicity, and invalid input.
3. Add route tests for exact request bodies, member/admin guards, request IDs, and typed failures.
4. Add central authorization regressions for active, perpetual, expired, missing, and duplicate subscription facts while preserving role and plan precedence.
5. Add organization-list and Admin UI contract tests for status rendering and canonical update payloads.
6. Run the focused tests first and record the expected RED failures before implementing product code.

## Implementation Sequence / 实现顺序

1. Implement migration 028 and register it in `db.js`.
2. Implement `subscription_expiry_service.js` and `routes_subscription_expiry.js`.
3. Wire the service into organization governance, central module authorization, and `server.js`.
4. Add the compact Admin organization subscription control in `app.js`.
5. Advance migration/release/sanitizer manifests and deployment pins to schema v28.

## Verification / 验证

- Ordinary feature releases run exact affected tests, required safety checks, and one independent review before immediate production deployment.
- Because this slice changes schema, authentication projection, and central authorization, it triggers the expanded migration replay/integrity, auth, authorization, browser, performance, production-shape, syntax, secret-scan, and release-inventory matrices.
- Future low-risk slices return to the lightweight feature-by-feature gate; heavy matrices are reserved for schema, authentication, authorization, tenant-authority, shared-infrastructure, or real external-write changes and phase closeout.
- After review: commit and push, create and verify a production backup, deploy immediately, then verify public health, schema v28, member subscription read, a short reversible `perpetual -> expired -> perpetual` admin round trip, governed-action denial during expiry, exact audit rows, no session revocation, PM2/Nginx health, database integrity, and frozen PPT hash.

## Release Exclusions / 发布排除

Billing, pricing, payment collection, shared organization quota, persistent concurrency reservations, AI-plan gating, catalog editing, notifications, grace periods, self-service renewal, and broad interface redesign remain separate feature releases.
