# v0.9.24 Subscription Expiry Control Design

## Objective / 目标

Deliver one independently useful Phase 8 capability: a server-owned organization subscription expiry term that immediately gates every governed organization action after expiry. Login, the authenticated shell, subscription status reads, and platform-administrator renewal remain available so an expired organization can be diagnosed and restored.

交付一个可独立上线的阶段 8 能力：由服务端权威维护组织订阅到期时间，到期后立即阻断所有受管组织业务动作。登录、已认证平台外壳、订阅状态查询及平台管理员续期入口继续可用，确保到期组织可被诊断并恢复。

## Release Cadence / 发布节奏

- One feature, one production release. Deploy immediately after affected tests, mandatory risk-triggered gates, one independent review, a verified backup, and focused online acceptance pass.
- Ordinary slices use exact affected tests and required safety checks. Schema, authentication, authorization, tenant authority, shared-infrastructure, or real external-write changes trigger the corresponding full release matrices. This slice changes schema and central authorization, so the expanded migration, auth, authorization, browser, and production-shape gates are mandatory.
- The latest application shell, customer screens, M3/M4 flows, AI/knowledge behavior, and frozen `ppt.js` remain unchanged.

## Authoritative Model / 权威模型

- `organization_subscription_terms` is independent from `organization_plan_assignments` so a plan change cannot reset or rewrite the subscription term.
- Terms are append-only. The unique highest `term_version` is authoritative; update and delete are forbidden.
- `expires_at = NULL` means perpetual. A non-null value must be canonical UTC RFC3339 seconds (`YYYY-MM-DDTHH:mm:ssZ`).
- Existing organizations are backfilled with perpetual term version 1. New organizations receive the same default from an insert trigger.
- Status is derived at read time as `perpetual`, `active`, or `expired`; no cached browser or JWT claim is authoritative.

## Authorization Contract / 授权合同

For organization-scoped module actions, the server evaluates live facts and enforces:

`role permission intersection active plan entitlement intersection unexpired subscription`

- The seven governed modules remain `crm.customer`, `crm.opportunity`, `crm.contact`, `crm.task`, `campaign.performance`, `campaign.customer_report`, and `influencer.data`.
- Platform administration is outside organization subscription expiry.
- If the role permits an action and the plan contains the module but the subscription is expired, authorization returns `SUBSCRIPTION_EXPIRED`.
- Role denial remains `ACTION_FORBIDDEN`; plan denial remains `PLAN_ENTITLEMENT_REQUIRED`.
- Missing, duplicate, or unreadable subscription facts fail closed as `ENTITLEMENT_POLICY_UNAVAILABLE` in the central authorization chain.
- Projection returns an empty action list after expiry, keeping login and `/api/auth/me` usable while preventing governed work.
- Expiry is effective when `expires_at <=` the request's single captured server UTC time. Each admission decision uses one subscription snapshot; an action already admitted is not cancelled midway if the clock crosses the boundary.
- HTTP wrappers preserve their route-specific error code and add the stable `reason_code: SUBSCRIPTION_EXPIRED`; unavailable policy returns HTTP 503 rather than being reported as an invalid login token.

## Service And API Contract / 服务与接口合同

- `GET /api/organization-subscription`: authenticated active organization members; returns the authoritative subscription projection.
- `PUT /api/admin/organizations/:organizationId/subscription`: active platform administrators only; exact body `{ expires_at, expected_version, reason }`.
- `expires_at` is either `null` for perpetual or canonical UTC RFC3339 seconds. Extra fields, proxies, malformed dates, non-canonical values, and missing reasons fail closed.
- Updates use exact compare-and-swap on `expected_version`. Repeating the current expiry is idempotent and writes neither history nor audit.
- The organization governance list includes the subscription projection. Only platform administrators receive `manage_subscription: true`.

## Audit And Failure Semantics / 审计与失败语义

- A successful change appends `organization_subscription_expiry_changed` to `activity_log` in the same immediate transaction as the new term.
- Audit details include actor, organization, before/after expiry and term version, reason, and request ID.
- Audit failure rolls back the term change.
- Stale versions return `409 SUBSCRIPTION_TERM_VERSION_CONFLICT`.
- Subscription service fact failures return `503 SUBSCRIPTION_POLICY_UNAVAILABLE`; central module authorization maps the unavailable policy chain to `ENTITLEMENT_POLICY_UNAVAILABLE`.

## Admin Interaction / 管理端交互

- Add one compact subscription column to the existing organization table; do not redesign the Admin page.
- Display `永久`, `有效至 ...`, or `已到期 ...`.
- Platform administrators get a `datetime-local` input and save action. Blank means perpetual; the browser converts a selected local time to canonical UTC before sending.
- Saving requires a 1-500 character reason and refreshes the authoritative organization list after success.
- A stale compare-and-swap refreshes the list before showing the conflict. Expired members see a compact read-only status band in the authenticated shell.

## Explicit Exclusions / 明确排除

No billing, pricing, payment collection, seat billing, monthly organization quota, persistent concurrency reservation, AI-plan gating, catalog editing, self-service renewal, grace period, notification automation, or broad UI redesign is included. AI chat, knowledge-base retrieval, proposal generation, and PPT generation are intentionally unaffected by subscription expiry in this release.
