# v0.9.25 Organization Monthly Shared AI Quota / 组织月度共享 AI 配额

## Goal / 目标

Add one organization-owned UTC calendar-month AI Token budget that is enforced by the existing central AI admission service before any provider request. Keep the existing per-user lifetime quota as a compatible secondary guard.

新增组织级 UTC 自然月 AI Token 共享额度，并由现有中央 AI 准入服务在任何模型请求前统一拦截。现有用户终身累计配额继续保留，作为兼容性的第二层限制。

## Product Contract / 产品契约

- The monthly window is fixed to UTC, from the first day 00:00:00Z through the first day of the next month. No organization timezone is introduced in this release.
- `monthly_limit = null` means unlimited, `0` means disabled, and a positive safe integer is the shared monthly limit.
- Existing and newly created organizations default to unlimited, so deployment does not silently disable current AI workflows.
- Ordinary users must pass both organization monthly quota and existing personal lifetime quota. Organization denial is evaluated first and returns a distinct error code.
- Active platform administrators remain break-glass exempt for compatibility only after the organization policy and ledger pass validation. Their recorded usage still contributes to organization monthly usage, and bypassing a disabled or exhausted policy writes `ai_quota_break_glass_admitted`.
- A quota policy update is append-only, version checked, reason required, and audited. Reads fail closed if the policy or usage ledger is unavailable or structurally invalid.
- Historical and future `token_usage.created_at` values must be canonical UTC seconds so monthly range queries cannot silently omit malformed rows.
- This release does not reserve quota before concurrent provider calls. It is a soft admission limit: concurrent overrun has no contractual upper bound and is explicitly assigned to the next persistent-reservation release.

- 月度窗口固定采用 UTC，自每月 1 日 00:00:00Z 至次月 1 日 00:00:00Z；本版本不引入组织时区。
- `monthly_limit = null` 表示不限额，`0` 表示停用，正安全整数表示组织共享月额度。
- 存量组织和新建组织默认不限额，部署后不会静默关闭现有 AI 工作流。
- 普通用户必须同时通过组织月度额度与现有个人终身额度；优先判定组织额度，并返回独立错误码。
- 活跃平台管理员仅在组织策略与账本校验通过后保留应急豁免；其用量仍计入组织月度用量，突破停用或耗尽状态时写入 `ai_quota_break_glass_admitted` 审计。
- 配额变更采用只追加历史、乐观版本校验、必填原因和审计日志；策略或用量账本异常时拒绝放行。
- 历史及未来的 `token_usage.created_at` 必须为规范 UTC 秒，防止月度范围查询静默漏算畸形记录。
- 本版本不做模型调用前的持久化额度预占，属于软准入限制；并发超额在合同上没有严格上界，持久预留能力进入下一独立版本。

## Data and API / 数据与接口

- Schema v29 adds immutable `organization_ai_quota_policies` history and an organization/month usage index on `token_usage`.
- `GET /api/organization-ai-quota` returns the active member's current organization monthly projection.
- `PUT /api/admin/organizations/:organizationId/ai-quota` accepts exactly `monthly_limit`, `expected_version`, and `reason`.
- Organization directory rows expose `ai_monthly_quota` and `allowed_actions.manage_ai_quota` for the existing Admin organization table.
- Projection fields include `used`, `limit`, `remaining`, `overage_tokens`, `utilization_percent`, status, UTC period boundaries, and policy version. Unlimited and zero-limit utilization remain `null` rather than reporting a misleading percentage.
- Denials use `AI_ORGANIZATION_QUOTA_DISABLED` or `AI_ORGANIZATION_QUOTA_EXCEEDED`; personal quota codes remain unchanged.

## Reversible Production Acceptance / 可逆线上验收

1. Verify a production-shaped sanitized copy upgrades to schema v29 twice, preserves the Token ledger, passes integrity/foreign-key checks, and restores from the recorded backup.
2. Record one target organization's original limit and version, set the organization limit to `0`, and verify a normal member sees `disabled` with the expected UTC period.
3. Send one uniquely tagged AI request and prove it returns `AI_ORGANIZATION_QUOTA_DISABLED` before provider dispatch, without new Token usage, conversation output, or business artifacts, while writing one bounded denial audit.
4. Restore the exact original limit using the next policy version, verify contiguous append-only history and change audits, then remove temporary sessions and test data. Any failed mandatory check triggers the recorded database and code rollback.

1. 在类生产脱敏副本上证明 schema v29 连续迁移两次、Token 账本不变、完整性与外键检查通过，并能从已记录备份恢复。
2. 记录目标组织原额度和版本，将组织额度设为 `0`，确认普通成员看到 `disabled` 及正确 UTC 周期。
3. 发送唯一标记的 AI 请求，证明在 Provider 调用前返回 `AI_ORGANIZATION_QUOTA_DISABLED`，且 Token、对话结果和业务产物均不新增，同时只写一条有界拒绝审计。
4. 使用下一策略版本精确恢复原额度，验证只追加历史连续且变更审计完整，再清理临时会话与测试数据；任一强制项失败即按记录执行数据库与代码回滚。

## Release Boundary / 发布边界

Included: migration, monthly usage projection, central admission, exact-body admin API, member read API, Admin organization control, audit logs, focused migration/auth/quota/UI/release-gate tests, backup, production deployment, reversible online acceptance.

Excluded: persistent reservations, billing and overage purchase, per-team budgets, local-time billing periods, alerts, historical charts, provider pricing conversion.
